Follow-up to [[project_shade_material_ux_findings]]. The "persistent nav" idea from that UX audit got its own full brainstorm → spec → plan → subagent-driven implementation cycle on 2026-07-06, branch `feat/lab-navigation-redesign`.

**What shipped:** a two-tier collapsible sidebar (shadcn `Sidebar`, previously a dormant/unused component — verified fully wired, zero fixing needed, adopted as-is rather than building new) replacing the header-dropdown nav pattern. Tier 1 "Destinations" (always visible: Workbench, Production, New Case, Catalog, Color Setup, Recommendations, Settings). Tier 2 "Current Case" (6-stage progress, only when a case is open, replaces the old horizontal stage tab strip — not duplicated alongside it). New `ActiveCaseContext` bridges the sidebar and `LabWorkbench`: `registerLeaveGuard`/`requestNavigation`, not a lifted `isDirty` boolean, so the sidebar routes through the *existing* `guardLeaveActiveStage` + `AlertDialog` unsaved-work mechanism instead of a second one.

**Key reversed decision:** hover-to-expand was the initial plan; an agy adversarial design review flagged it as a real anti-pattern (Fitts's-law edge-hover accidents, layout jitter, breaks on touch — relevant since technicians may use tablets at the bench, often gloved). Reversed to click-only, which also matched the adopted `Sidebar` component's real default behavior.

**Real bugs caught and fixed during implementation** (subagent-driven-development, 8 tasks + per-task review + final whole-branch review):
- Task 6 (shrink Header) initially deleted the *clinic* role's only nav link to `/clinic-dashboard` as a side effect of removing lab-only nav — plan explicitly scoped "no clinic changes," caught by per-task review, fixed + regression-tested.
- Task 8 found `LabWorkbench` is also mounted at `/clinic-dashboard` (staining-clinic hybrid view), unwrapped in the new context — would have crashed that page. User explicitly authorized wrapping that route's `ActiveCaseProvider` too (real reason given: clinic's own case-creation flow should get this coverage, not just avoid a crash).
- Final whole-branch review (opus) caught two more cross-task bugs no single per-task review could see: (1) `LabAppLayout`'s `Header`+sidebar were row-flex siblings instead of stacked — visually confirmed and fixed via a throwaway auth-bypass mock route, since placeholder Supabase creds block real login in dev; (2) moving `/settings` under the new layout accidentally gave clinic users the lab sidebar (same regression class as the Task 6 bug) — fixed by moving it back to a standalone route.

**Round 4 (2026-07-07) — real functional bugs, not styling, found via live-preview clicking:**
- **Clicking an existing case card did nothing visually**, though console proved data loaded correctly (progress hydrated, teeth switched). Root cause chain, found by direct code tracing (not by trusting a subagent's first guess — first investigator dispatch theorized wrong twice before I traced it myself): `LabWorkbench.tsx` had a `useEffect` — "close case when url has no case param" — left over from the sidebar deep-link feature (`?case=<id>&stage=<stage>`). Queue-click selection (`handleCaseSelect`) never set that URL param, so the instant a case was selected the effect saw `!caseIdFromUrl && selectedCase` and immediately nulled it back out — a self-cancelling selection. Fixed by deleting the effect (commit `2dbdec0`); confirmed via full trace that the deep-link path strips its own param immediately anyway and all 4 explicit-close call sites (`setSelectedCase(null)`) are untouched by the removal.
- Fixing #1 exposed a **second real bug it had been masking**: the case-detail panel's outer wrapper only got its height class (`h-[calc(100vh-180px)]`) when `!selectedCase` — once a case opened, the flex column had no height source and `flex-1`/`min-h-0` descendants collapsed to 0px, invisible even though state/data were correct. Fixed (commit `3e5e5af`) by applying the height class unconditionally.
- Opening **New Case** (`?view=new`) white-screened with `Uncaught ReferenceError: Cannot access 'Tr' before initialization` — looked like a circular-import TDZ bug (that's the classic cause of this exact error class in a Rollup/Vite prod bundle) but two independent deep investigations (one Claude subagent running `madge --circular` + fresh local rebuild + Playwright, one `agy`/Gemini pass) both found **zero circular imports** and could not reproduce on a fresh local build — strong signal it wasn't a cross-file cycle. A third, more thorough Claude pass with real authenticated repro (`lab-test@gavan.ai` synthetic account, real `michael`-schema Supabase project) found the actual cause: `OrderWizard.tsx` had a `useMemo` (`validationByStep`) referencing `isStep1Valid`...`isStep6Valid` ~450 lines *before* those consts were declared in the same component. Vite dev (esbuild) tolerates this; Rollup's prod bundle enforces strict declaration order → TDZ crash on first render, only in the built bundle, never in dev. Fixed by moving the memo+effects below the const declarations (commit `e4179cf`). Also caught and fixed a second latent bug along the way: `CaseList.tsx` was missing `onCreateInternalCase` from its destructured props (added elsewhere as a type+usage but never destructured) — would have thrown separately once reached. Neither bug was caught by bare `npx tsc --noEmit` at repo root, because `tsconfig.json` has `"files": []` and delegates via project references — `npx tsc -p tsconfig.app.json` is the command that actually type-checks app source; worth remembering for any future verification on this repo.
- Fixing #2 (unconditional height) then clipped the **Staining Instructions** stage — no internal scroll region, content taller than the fixed height was hard-cut with no scrollbar. Root cause: the shared `Tabs` wrapper had `overflow-hidden` (fine when the outer height was unbounded, broken once bounded). Fixed by switching it to `overflow-y-auto` (commit `4187bb9`) — stages with their own internal `ScrollArea` are unaffected (bounded by `min-h-0`/`flex-1` first), this is only the safety-net scroll for stages without one.
- Separately, fixing #1 (deleting the URL-watching effect) **broke the sidebar's "Lab Workbench" back-navigation** while a case was open — since the queue-click and deep-link paths both leave the URL with no `case=` param while a case is open, clicking "Lab Workbench" (`navigate("/lab-workbench")`, already the current URL) was a router no-op, nothing closed the case. Real gap in round 1's leave-guard wiring, exposed by the round-4 fix. Fixed properly (commit `66faea2`) by adding an explicit close channel to `ActiveCaseContext` (`registerCloseActiveCase`/`requestCloseActiveCase`, same ref-registration pattern as the existing leave-guard) rather than reintroducing any URL-diffing effect — `LabSidebarDestinations.tsx`'s Lab Workbench click now calls `requestCloseActiveCase()` (which still runs the leave-guard first) before navigating.
- **Lesson reinforced:** a fix that resolves the reported symptom can unmask or introduce an adjacent bug in the same render path — after each of these fixes, explicitly grepped/traced the other code paths touching the same state (explicit-close sites, deep-link effects, sidebar nav) before considering it done, rather than declaring victory on the first green result.
- Michael flagged one more UX-only issue in this batch (stage-lock over-aggressiveness on back-navigation — should only lock if a real dependency+change blocks going back) — deliberately not dispatched yet, queued to avoid a second concurrent agent editing `LabWorkbench.tsx` while the round-4 fixes were in flight.

**Round 6 (2026-07-08) — the `h-svh`/`overflow-hidden` shell fix from Round 5 overcorrected: Material Catalog and other pages lost vertical scroll entirely, not just "clipped."** Root cause: `LabAppLayout`'s Outlet wrapper was `overflow-hidden`, and pages were expected to self-supply a scroll region via a guessed `h-[calc(100vh-180px)]` pixel constant.
